## 2026-11-22 特性の割合・1日5分

- **指摘**: 昼寝好きなど珍しい特徴を持つ人が多すぎる。→ 原因は、特性を 0〜1 の一様乱数で決めていて、各特徴が約25%に付いていたこと。釣り鐘型の分布にし、人数分の分位点を並べて割り当てる形にした([03-sleep.md](03-sleep.md))。50人で、早起き5・夜更かし5・ショート2・ロング3・昼寝好き5。
- **1日を5分に**: 以前、1日240秒で村人が飢えたため、歩く速さの補正を心配した。実際には、行動の長さを「ゲーム内の時間」で書いてあるため、補正なしでも成り立った(極端な空腹 6.6%)。それでも歩く時間は相対的に長いので、平方根で×2の補正を入れた(4.5%)。×4(時間の比そのまま)は 2.6% だが、走っているように見えるので採らなかった([04-economy.md](04-economy.md))。

## 2026-11-22 3D試作

作ったもの・動かし方・測定結果は [02-prototype.md](02-prototype.md)。ここには試行錯誤を書く。

- **つまずき1: 村人の約75%がいつも歩いていた。** 描画なしで2日分を動かす `sim-check` で、時間帯ごとの行動を数えて発覚。原因は ai_cpu が、行動を選んだ瞬間から時間と欲求の回復を進めていたこと(酒場へ歩いている間に食べ終わっていた)。対策として、行動を「選ぶ」と「始める(着いた)」を分け、始めるまでは進めないようにした。→ 移動中の割合が約半分になり、各行動をしている時間が増えた。
- **つまずき2: 欲求がずっと0に張り付いた。** 1人の1日分の「やりたいこと」が、1日の長さを超えていた(減る速さ × 回復に要る時間+移動時間)。減る速さを約半分にして、時間平均で 0.3 前後、ほぼ0の割合 5〜15% になった。これは村の広さ・行動の長さ・1日の長さとセットで決まる値なので、世界を変えたら調整し直す。
- **つまずき3: 手前の村人が傾いて見えた。** 寝ているのかと疑ったが、カメラの角度が急で視野(FOV)が広いことによる遠近のゆがみだった。FOV を 60 → 48 にした。
- **道具の事情**: Claude in Chrome が繋がらず、Playwright の Chromium も必要なライブラリがなく動かなかったので、Windows の Chrome を `--headless --screenshot` で起動して画面を確かめた。実際のGPU・スマホでの性能は未確認。
- 村人のよけ方: 障害物の中心に向かうと正面で止まってしまうため、近づいたら接線方向へ曲げる処理を入れた。目的地(玄関など)のそばの障害物は、よけない。

- 会話の記録が 1 を押しても消えない不具合: 終了時に会話の相手を空にしていなかった。終了で即座に消すようにした。
