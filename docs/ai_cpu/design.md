# ai_cpu 設計

村人CPUの頭脳。**ゲーム・描画・世界の仕組みを一切知らない**純粋な計算の部品で、他のゲームにもそのまま持ち出せる。

## 約束事(これを破らない)

1. `ai_cpu/` の中から、ゲーム本体のコードを読み込まない。
2. 外とのやりとりは「知覚(入力)」と「意図(出力)」だけ。
3. 乱数は種(シード)つきの自前のもの。`Math.random` を使わない → 同じ種・同じ入力なら必ず同じ結果(再現できる・テストできる)。
4. 内部の状態は、すべてそのまま保存できる形(JSON)にできる → セーブ・ロードができる。
5. 実行環境に依存しない(ブラウザでも Node でも動く)。外部ライブラリなし。

## 登場する部品(v0)

| 部品 | 役割 | 置き場所 |
| --- | --- | --- |
| 乱数 `Rng` | 種つき・状態を保存できる乱数 | `src/core/rng.ts` |
| 型 | 知覚・意図・状態の形 | `src/core/types.ts` |
| 欲求 `needs` | 時間で減る値(満腹・睡眠・社交…)。ゲームが種類を決める | `src/agent/needs.ts` |
| 性格 `traits` | 0〜1 の値(外向性など)。行動の好みに効く | `src/agent/personality.ts` |
| 行動の定義 `ActionSpec` | ゲームが「できる行動」を登録する。何の欲求をどれだけ満たすか・誰が好むか | `src/agent/actions.ts` |
| 決定 `Agent` | 欲求・性格・状況から次の行動を選ぶ | `src/agent/agent.ts` |
| 記憶 | 最近したことの記録(いまは短い履歴だけ) | `src/agent/agent.ts` |
| スケジューラ | 村人が多いとき、近い村人を細かく・遠い村人を粗く考えさせる | `src/sim/scheduler.ts` |

## 行動の決め方(v0: ユーティリティAI)

行動ごとに点数をつけ、いちばん高いものを選ぶ。

```
点数 = Σ(その欲求の切迫度 × その行動が満たす量 × その人の敏感さ)
     + 性格の好み(行動ごとの性格への相性)
     + ゲーム固有の補正(状況に応じて、ゲームが足す)
     + ゆらぎ(種つき乱数。人間らしい気まぐれ)
     + 今の行動を続ける得点(コロコロ変えないための慣性)
```

- 切迫度は、欲求が低いほど急に大きくなる(満たされているうちは気にしない)。
- 行動には所要時間があり、終わるまでは基本的に続ける。ただし一定間隔で見直し、今より十分に良い行動があれば乗り換える。
- 行動の「中身」(歩く経路、会話の文面)はゲーム側が決める。`ai_cpu` は「何をしたいか」だけ返す。

## ゲームとのやりとり

```ts
// 毎回、ゲームが知覚を渡して、意図をもらう
const intent = agent.update(perception, dtSec)
// intent = { actionId: 'eat', startedAt, progress, engaged }

// 目的地に着いたら、ゲームが「始めた」と伝える
agent.engage()
```

- **知覚**: 時刻、ゲーム固有の事実(`facts`)、近くの存在(`entities`)。
- **意図**: 選んだ行動の id、進み具合、始めているか(`engaged`)。

### 「選ぶ」と「始める」を分ける(`requiresEngagement`)

食事は酒場へ行かないと始まらない。最初の版では、行動を選んだ瞬間から時間と欲求の回復が進んでいたため、歩いている間に「食べ終わる」ことになり、村人の約75%が常に移動中で、欲求も尽きた(試作で発覚。[../journal.md](../journal.md))。

そこで、行動に `requiresEngagement: true` をつけると、ゲームが `agent.engage()` を呼ぶまで、時間も欲求の回復も進まなくなった。`engageTimeoutSec`(標準150秒)待っても始められなければ、諦めて選び直す。歩く経路や到着の判定はゲーム側の仕事。

注意: 村人が遠くて考える間隔が長いとき(スケジューラ参照)、`engage()` から次の `update` までの時間は、行動の時間に数えられる。最大でも考える間隔(3秒)程度の誤差。

## 個性を表す汎用の仕組み

ゲームが特性(`traits`)の意味を決め、ai_cpu は次の仕組みだけを提供する。睡眠の個性([../03-sleep.md](../03-sleep.md))で使った。

| 仕組み | 内容 |
| --- | --- |
| `Personality.needSensitivity` | 欲求ごとの敏感さ。大きいほど、その欲求を満たす行動が選ばれやすい |
| `Personality.needDecayScale` | 欲求ごとの「減る速さ」の倍率 |
| `Personality.durationScale` | 行動ごとの所要時間の倍率 |
| `ActionSpec.traitAffinity` | 行動と特性の相性(その特性が高い人ほど好む/避ける) |
| `ActionSpec.inertia` | その行動を始めたら続けやすい度合い(睡眠のように途中で起きにくい行動は大きく) |
| `ActionSpec.cooldownSec` | 一度終えてから、また選べるようになるまでの時間(昼寝を1日1回に、など) |
| `AgentView.currentActionId` / `lastDone` | 条件・補正の関数から、いま続けている行動と、各行動を最後に終えた時刻が見える |

## 持ち物(お金・アイテム)

ゲームが意味を決める「持ち物」を、村人ごとに持たせられる。コンビニの買い物と賃金([../04-economy.md](../04-economy.md))で使った。

| 仕組み | 内容 |
| --- | --- |
| `AgentConfig.resources` | 持ち物の初期値(例: `{ money: 800 }`) |
| `Agent.getResources()` / `addResource(id, amount)` | 読み取りと、ゲーム側の出来事での増減。保存・復元できる |
| `ActionSpec.costs` | 行動を始めるときに払う持ち物。足りないと、その行動は選べない。`requiresEngagement` の行動は、`engage()` を呼んだ時点で払う |
| `ActionSpec.gains` | 行動を終えたときに手に入る持ち物。途中でやめると手に入らない |
| `AgentView.resources` | 判断の関数から、持ち物が見える(「お金が少ないほど働きたい」などの補正に使う) |

食べるときの食料品の消費も、`costs` で表している(`eat_onigiri` は `item.onigiri` を1個払う)。

## 村人が多いとき(スケジューラ)

`AgentScheduler` が、村人ごとに「何秒ごとに考えさせるか」(近い→短い、遠い→長い)と、1回の呼び出しで考えさせる人数の上限を受け取り、順番待ちの長い村人から更新する。重い処理で全員が一斉に止まらないようにするための仕組み。

## これから足すもの(v0 には入っていない)

- 行動の**対象**の選択(誰に話しかけるか、どの椅子に座るか)
- **人間関係**(好感度・信頼・噂の広がり)
- 記憶の本格化(忘れる・思い出す・感情のついた記憶)
- **気分**(欲求とは別の、短期の感情)
- 1日の**習慣・予定**(朝は畑、昼は食事、など)
- 他の村人の行動を見て学ぶ・真似る
- 性格が経験で少しずつ変わる

足すたびに、ここと [../journal.md](../journal.md) に書く。
